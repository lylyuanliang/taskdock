# 已知问题与发布风险

> 状态：持续维护。本文档记录确认过的缺陷、兼容性问题和发布验收缺口，不是功能需求清单；规划中的能力请写入[项目路线图](roadmap.md)。

## 使用规则

每条问题记录必须包含：

- 稳定的问题编号；
- 分类和严重程度或发布影响；
- 受影响的版本或环境；
- 实际现象和复现条件；
- 临时规避方式（如果有）；
- 当前状态；
- 预计修复里程碑，或明确说明尚未分配里程碑。

状态定义如下：

| 状态       | 含义                                                 |
| ---------- | ---------------------------------------------------- |
| 开放       | 已确认，等待调查或修复。                             |
| 已计划     | 已有修复方案，并安排到目标里程碑。                   |
| 进行中     | 正在实施或验证修复。                                 |
| 已验证     | 发布验收项已经检查，未观察到问题。                   |
| 已修复     | 修复已合并，并通过规定的验证；保留记录作为发布历史。 |
| 已接受风险 | 发布时已知，并由维护者明确接受了限制或规避方式。     |

用户报告问题时，先在这里记录可复现的现象；可自动化时补充回归测试。目标里程碑、规避方式或验证结果发生变化时，应更新对应条目。

## 关闭规则

- 只有修复合并且规定的验证通过后，才能将问题标记为已修复。
- 影响过已发布行为的问题不要删除，应移到已解决记录中保留历史。
- 阻塞里程碑完成标准的问题，必须在修复或明确接受发布风险前保持里程碑为“验收中”或“计划中”。
- 安全敏感问题不要在公开台账中写入密钥或可利用细节；公开文档只保留最小描述，敏感信息使用私下披露渠道。
