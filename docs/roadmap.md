# TaskDock 项目路线图

> 状态：持续维护。里程碑状态、范围、依赖或完成标准发生变化时，应同步更新本文档。

## 状态定义

| 状态   | 含义                                           |
| ------ | ---------------------------------------------- |
| 已完成 | 范围和完成标准均已满足。                       |
| 验收中 | 实现已经存在，但仍有必须完成的发布或用户验证。 |
| 进行中 | 正在准备或实施，但完成标准尚未满足。           |
| 计划中 | 范围已确认，但尚未开始实施。                   |
| 延后   | 已明确推迟，不代表当前有实施承诺。             |

自动化测试不能替代 Windows 原生安装版验收。发布风险和确认过的缺陷统一记录在[已知问题与发布风险](known-issues.md)中。

## 里程碑

| 里程碑                    | 状态   | 范围                                                                                                    | 完成标准                                                                     |
| ------------------------- | ------ | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| M0：项目基础              | 已完成 | Tauri/React/Rust/SQLite 项目、本地持久化、国际化、主题策略和 Windows 开发流程                           | 仓库可以本地构建，桌面基础架构建立。                                         |
| M1：本地核心工作流        | 已完成 | 任务创建、完成与恢复，收件箱/今天/即将开始/已完成/项目/月历视图，项目管理、搜索和本地数据               | 核心工作流实现，并有自动化测试覆盖。                                         |
| M2：可靠桌面工作流        | 已完成 | 任务编辑字段、直属子任务、标签、重复规则、乐观版本、提醒、跨窗口同步、快捷面板点击/拖动和 TaskDock 品牌 | 自动化质量门禁通过；用户确认初版 Windows 安装版验收无问题。                  |
| M3：`v0.1.0` Windows 发布 | 进行中 | 最终发布检查、安装包构建、数据兼容说明、Git 标签和 GitHub Release                                       | 发布包构建并安装成功，发布说明和 `v0.1.0` 已发布。                           |
| M4：WebDAV 同步           | 计划中 | WebDAV 配置、同步边界、冲突处理和坚果云兼容说明                                                         | 两个配置好的本地实例能够同步，且不会静默丢失数据；离线和冲突行为有明确说明。 |
| M5：本机 Web 门户         | 延后   | 仅由同一台 Windows 桌面应用提供服务的浏览器门户                                                         | 浏览器操作使用桌面应用拥有的任务服务，不引入远程或托管访问。                 |
| M6：AI 服务边界           | 延后   | 可选的 OpenAPI 兼容 AI 适配器和用户配置                                                                 | 有类型化服务契约、用户同意边界、错误处理，并且不直接访问数据库。             |
| M7：Android 与跨平台      | 延后   | Android 客户端和共享的可移植契约                                                                        | 核心任务数据与行为可以在 Android 工作，不引入 Windows 专属展示行为。         |
| M8：内容与协作扩展        | 延后   | 附件、评论和更丰富的项目协作工作流                                                                      | 数据、隐私、同步和迁移设计在实施前获得确认。                                 |

## 当前发布重点

项目已经完成 **M2**，当前正在准备 `v0.1.0` Windows 发布。本轮主窗口 Stitch 视觉骨架、任务展示、项目任务板和月历任务条已实现，并通过单元测试、业务 E2E 和固定视口视觉回归；初版 Windows 安装版人工验收也已由用户确认无问题。默认入口和专注统计数据源仍按[已知问题与发布风险](known-issues.md)记录。

在将 M3 标记为已发布前：

1. 在 `main` 上重新运行前端、Rust、格式、Lint 和构建检查。
2. 构建并安装选定的 Windows 安装包，记录准确的产物和版本。
3. 创建并推送 `v0.1.0` 标签，发布 GitHub Release 说明和安装包。
4. 每发现一个确认过的缺陷，都要在[已知问题与发布风险](known-issues.md)中填写预计修复里程碑。

本轮快捷面板入口、重复启动单实例、收拢按钮语义和退出入口问题已完成代码修复，记录在[已知问题与发布风险](known-issues.md)的 `BUG-2026-001` 至 `BUG-2026-004`；仍需在 Windows 安装版上完成窗口操作和退出流程的人工验收。

## 里程碑维护规则

- 功能合并不等于里程碑完成；必须满足该里程碑的完成标准。
- 验收失败项必须归类为确认缺陷或已明确接受的发布风险。
- 新产品工作开始前，必须归入已有里程碑，或先新增一个里程碑。
- 已知问题可以指定目标里程碑，但目标本身不代表问题已经修复。
