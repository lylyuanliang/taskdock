# TaskDock 项目路线图

> 状态：持续维护。里程碑状态、范围、依赖或完成标准发生变化时，应同步更新本文档。

## 状态定义

| 状态   | 含义                                           |
| ------ | ---------------------------------------------- |
| 已完成 | 范围和完成标准均已满足。                       |
| 验收中 | 实现已经存在，但仍有必须完成的发布或用户验证。 |
| 进行中 | 正在准备或实施，但完成标准尚未满足。           |
| 计划中 | 范围已确认，但尚未开始实施。                   |
| 延后   | 已明确推迟，不代表当前有实施承诺。             |

自动化测试不能替代 Windows 原生安装版验收。发布风险和确认过的缺陷统一记录在[已知问题与发布风险](known-issues.md)中。

## 当前发布重点

项目已经完成 **M3**，`v0.2.0` Windows 正式版已发布，发布后复验已完成。本轮主窗口 Stitch 视觉骨架、任务展示、项目任务板和月历任务条已实现，并通过单元测试、业务 E2E 和固定视口视觉回归。

**M4 当前状态：** `codex/webdav-sync-m4` worktree 已完成 WebDAV 同步实现和自动化验证，但尚未合并到主分支或随正式版本发布。已交付内容包括：单个 WebDAV 配置、Windows 凭据管理器保存凭据、默认开启且可关闭的 Argon2id + AES-256-GCM 快照加密、本地优先三方合并、字段级冲突决策、启动/写入唤醒/五分钟轮询同步 worker，以及同步设置、首次同步和冲突处理页面。当前自动化验证使用内存仓储、模拟 WebDAV 和 Playwright E2E；真实 WebDAV 服务与 Windows 安装版验收仍是 M4 的退出条件。

完成 M4 合并与发布前：

1. 对已发布安装包执行一次发布后复验，更新已知问题的状态和实际版本。
2. 每发现一个确认过的缺陷，都要在[已知问题与发布风险](known-issues.md)中填写预计修复里程碑。
3. 使用真实 WebDAV 服务完成至少一次首次同步、双向修改、认证失败、暂停/恢复和冲突决策验收，并记录结果。

本轮快捷面板入口、重复启动单实例、收拢按钮语义和退出入口问题已完成代码修复，记录在[已知问题与发布风险](known-issues.md)的 `BUG-2026-001` 至 `BUG-2026-004`；发布后已根据实际安装包验收结果关闭或保留对应记录。

## 里程碑维护规则

- 功能合并不等于里程碑完成；必须满足该里程碑的完成标准。
- 验收失败项必须归类为确认缺陷或已明确接受的发布风险。
- 新产品工作开始前，必须归入已有里程碑，或先新增一个里程碑。
- 已知问题可以指定目标里程碑，但目标本身不代表问题已经修复。
